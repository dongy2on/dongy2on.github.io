Automatic Screen Lock Program for Privacy & Security

Data Literacy Foundations (EF1003)  ·  Team 03 (Han Ye Gang, Dongyeon Kwon)
1. Idea & Motivation

Leaving a computer unattended can easily expose sensitive information to anyone nearby. While manual locking is the standard procedure, it is often forgotten—especially in busy environments like libraries, offices, and research labs.

To solve this problem, we developed a real-time webcam monitoring system that detects whether a person is present at the desk. If the seat remains empty for 5 consecutive seconds, the program automatically locks the Windows screen, providing a practical, lightweight, and immediately usable security layer.

2. Development & Implementation
Python OpenCV TensorFlow / Keras Teachable Machine Windows API (ctypes)

A. Data Collection & Curation
We captured a total of 506 training samples via webcam. To ensure robust detection, we collected 370 'person_existed' images (including single and multiple persons) and 136 'no_person' images featuring empty chairs and desks with various backgrounds and lighting conditions.

B. AI Model Training
Utilizing Google Teachable Machine, we trained a lightweight AI model based on MobileNet (Transfer Learning). The model was trained over 50 epochs with a batch size of 16, resulting in a highly accurate binary classification system.

C. System Integration
The core logic was implemented in Python (`main.py`). The program uses OpenCV to capture and preprocess real-time video frames, feeds them into the Keras model for inference, and utilizes the ctypes API (`LockWorkStation`) to trigger the OS-level lock screen if the "no_person" state persists for the set timer duration.

3. Demo Results & Future Outlook

A. Live Demonstration Performance
The program successfully operates as a continuous background process. When a user is detected, the program displays a green status text showing the confidence score. The moment the user leaves the frame, a red 5-second countdown initiates, reliably executing the Windows screen lock precisely as intended.

B. Limitations & Future Improvements
Currently, the implementation relies on the Windows-specific ctypes API. Future iterations aim to introduce cross-platform support (macOS/Linux), implement adjustable lock delays via a configuration file, and add audible alerts before locking to accommodate edge cases like extreme lighting or partial occlusions.
